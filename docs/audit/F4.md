## Open issues

1. **Medium, F4-owned: "use 24 months when available" is not applied, and the mitigating warning misses common cases.** The design-day window is always `projection.trailing_months` (default 12). The warning `design_day_window_below_24_months` needs 24 whole calendar months, so a 730-day history ending on 30 December does not trigger it. The interpretation ("24 is guidance for the basis author") still needs a register entry.
2. **Medium, F4-owned: basis validation is incomplete.** `check_basis` does not reject a negative or NaN `peak_stock_factor`, a negative or NaN `inbound_peak_factor`, or `growth_rate = inf`. These load and produce negative, NaN or infinite design values that would flow into storage and dock sizing.
3. **Medium, cross-feature: the `select_design_day` signature differs from the spec.** Derived inbound mode (the default) needs `sku=with_pack_data(tables.skus, canonical sku_master)`. Without it, `WhsizingError` names the fix. F8 must pass it, and the contract should be registered in `docs/INTERPRETATIONS.md` (not F4-owned).
4. **Low, F4-owned:** `F_RATIO_DRIFT` is not raised when P_m = 0 and m* > 0. This is an undocumented choice.
5. **Low, F4-owned:** the unregistered flag code `F_DEFAULT_UPP` appears twice in the DesignDay JSON (once in `inbound.flags`, once in `flags`). It needs an I46 register entry, or a decision to keep it only in `Inbound.flags`.
6. **Low:** no assumptions row for an empty `overrides` field, so T4.5 does not check the literal property for that field. Done-when "the assumptions list renders in the report" cannot be checked until F9 exists.
7. **Low, register:** the receipts-mode choices are unregistered (P_p × (1+g)^T, unknown-pallet days dropped, peak_factor applied on top of percentile values).
8. **Low, F4-owned:** with `catalog=None`, the result depends on the working directory (`./catalog`).
9. **Low, F4-owned (nit):** the inbound peak-factor fallback uses the whole history, while the other inbound quantities use the candidate window.
10. **Low, observed while writing this record, not a recorded auditor finding:** the auditor's `round2.py` section 11 shows that a `daily` frame missing a metric column raises a raw `polars.exceptions.ColumnNotFoundError: "cube_m3" not found` instead of a `whsizing.errors` class. F3 builds `daily` with all columns, so this only matters for hand-built input.
11. **Unaddressed:** the round-0 spec audit text was clipped after the 9th finding. Any later findings were never seen or addressed.
12. **Cross-feature note (not broken today):** F2 fills `units_per_pallet` with its own 400. A basis override of `storage.default_units_per_pallet` reaches only SKUs that F2 did not fill, unless F8 passes the override to `ingest`.
