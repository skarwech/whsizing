## Open issues

1. **MEDIUM, open, F10b: page 3 re-profiles on every script run for a profiled-but-not-sized run.** `state.profile_stale` compares every `canonical/*.parquet` mtime to `demand_profile.json`, and `canonical/daily_series.parquet` is written right after it by the profile step, so the check is always True. Each page-3 script run (visit, language toggle) re-runs `profile`, takes about 1.4-1.6 s, and rewrites `demand_profile.json`, `daily_series.parquet` and the charts. The audit reported the repeated work and rewritten files; it did not report wrong numbers from it. Sized runs are unaffected (`profile_stale` returns False once sized). Audit-proposed fix, verified only in a scratch copy: exclude `canonical/daily_series.parquet` from the stale check. Neither `test_T10_4_page_3_reprofiles_...` (renders twice only) nor `test_T10_4_profile_is_stale_...` (fakes mtimes) would fail on this bug, so a test that renders page 3 three times after a real `profile` and asserts the file mtime stays constant is also missing.
2. LOW, deferred: the drill-down is started from a selectbox of Summary cells and a trace-id field, not by clicking a cell (spec wording: "click a cell: tracer.tree(id)"). The tree, depth slider and re-root are correct (proof 3).
