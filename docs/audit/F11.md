## Open issues

1. **Medium, F11: complete edge months dropped as partial** (round-1 finding 10, a regression from the round-1 fix). `fit.py:111` compares the daily-series coverage with exactly 1. A calendar-year extract whose Jan 1 is a holiday or which ends on a Sunday or holiday loses those months and can lose the true peak month from the hold-out. Not fixed.
2. **Low, F11: all-partial extract gives a misleading error** (finding 11). Not fixed.
3. **Low, F11: undeclared client activities are an error, not auto-added** (finding 4/12). Deliberate design; the declared path works. A declared client activity is only reported (`fit.json` and the note); it is not used by any catalog or sizing.
4. **Low, spec limit: PF&D is confounded with the multipliers** (finding 6/13). A literal reading of T11.1 holds for the effective multiplier m x (1 + PF&D basis) / (1 + PF&D) and for the raw m only when the truth PF&D equals the prior. Tests assert effective, and raw only where the truth PF&D matches the basis.
5. **Docs owner, outside F11 paths:** register the F11 interpretations and flag codes (`F_CALIB_ERROR`, `W_HOLDOUT_SHIFTED`, `W_PARTIAL_MONTH`, `W_MISSING_MONTH`, `W_UNMAPPED_ACTIVITY`, `W_NO_ACTUALS`, `W_SHORT_HISTORY`, `F_CLIENT_ACTIVITY`, `I_HEADCOUNT_ONLY`, `I_TEMPS_COMBINED`) in `docs/INTERPRETATIONS.md`, and fill the "Calibration (F11)" section of `docs/methodology.md`, which is still `TODO (F11)` (checked for this record). The list is in the docstring of `src/whsizing/calibration/__init__.py`. Interpretations to register include: one multiplier per F6c table row; hours linear in 1/productivity and (1 + PF&D), so the engine runs once; eta stays at its prior (I38); effective multiplier; `NOISE_REL = 0.003` and `F_SCALE = 2` (the engineer's choices within the spec); peak month and hold-out shift; partial-month exclusion; headcount-only conversion with `annual_paid_hours_per_fte / 12`; `temp_hours` informational; predicted peak lines/h definition.
6. **F10, outside F11 paths:** `calibrate()` reads `actuals.csv` and `activity_map.yaml` from arbitrary paths and writes only its own outputs into the folder it is given (F10 should pass `<run>/calibration`); F10 must copy or hash the inputs, and must decide the mapping of `DataQualityError` (exit code 3 in `errors.py`) against the spec CLI table, which lists 0/2 for `calibrate`.
